# Breeze TTS（astrbot_plugin_breeze_tts）

**v3.7.8**

把 BreezeBlue（Breeze-TTS-2）接进 AstrBot 的原生语音回复流程，**任意音色**都能用，插件本身不预设任何角色。

## 为什么要这样接

AstrBot 的「新建模型提供商」列表是**内置固定**的 13 张卡片（OpenAI TTS、Edge TTS、Azure TTS…），插件没法往里加新卡片——试过注册新提供商类型，下拉里不会出现。

所以这个插件在 AstrBot 进程内起一个 **OpenAI 形状的 TTS 端点**，然后你用列表里现成的 **OpenAI TTS(API)** 卡片指向它。因为插件和 AstrBot 在同一个容器里，`127.0.0.1` 直接可达，**不需要额外跑容器、不需要改 docker compose**。

## 用法（三步）

### 1. 装插件

WebUI → 插件 → 安装 `astrbot_plugin_breeze_tts.zip`。装好后端点自动起在 `127.0.0.1:8788`。
端口被占就在「插件 → 本插件 → 配置」里改 `port`，重启插件生效。

关于端口，插件有三层保护：

- 插件重载后旧端点还在监听，新实例会直接**复用**它，不会报 `Address already in use`
- 配置会写到插件目录下 `runtime_config.json`，复用的是旧端点也能读到新 Key
- 8788 真被别的程序占用时，自动顺延到 8789/8790…，日志和 `/tts状态` 会打出**实际端口**，按那个改提供商地址即可

### 2. 建提供商

「服务提供商 → 新增」→ 选 **OpenAI TTS(API)**：

| 字段 | 填什么 |
|---|---|
| API Base URL | `http://127.0.0.1:8788/v1` |
| API Key | 你的 Breeze Key（`brz_` 开头）；也可以留空，由插件配置里的 `api_key` 提供 |
| 模型 ID | `breeze-tts-2`（其他语种用 `breeze-tts-2-multilingual`） |
| voice | 音色 ID，必须是 `voc_` 开头，例如 `voc_u3nxkd5578wc` |
| 超时时间 | 60 秒以上（跨境 + 排队，20 秒会掐断） |
| 代理地址 | 留空（这是 AstrBot 的出站代理，别和插件端点的地址搞混） |

保存后打开「启用」。

### 3. 接进语音回复

「AI」页：打开 **语音回复** → **默认文本转语音模型**选刚建的提供商 → TTS 触发概率 1。

音色 ID 有两处可填，**先看 AI 页那一项**：

1. **AI 页「语音回复」下面**（插件注入的）：打开语音回复后，这一组最末尾会出现 **语音回复音色 ID**（在「TTS 触发概率」之后）
2. **插件 → Breeze TTS → 配置 → 语音回复音色 ID**（备用，标签由插件自己控制，任何时候都正常）

两处都生效，优先级：**AI 页那一项 > 插件配置 `voice_id` > 提供商表单的 `voice`（仅 `voc_` 开头才认）> `default_voice`**。

- 想给不同机器人不同音色时，这两项是全局的，就别填，改用「多个提供商 + `/provider tts`」那条路
- 3.7.8 里这一项**不会随语音回复开关收起**：`condition` 是内置项用的，插件加进去并不生效（加了也没用，所以拿掉了）

> **为什么它在「TTS 触发概率」后面而不是紧贴开关**：试过直接插在开关下面，结果内置的「默认文本转语音模型」「TTS 触发概率」两行在配置页上直接不显示。
> 插件侧的数据是完整的（测试里断言过顺序），问题出在配置页渲染：往这组里插一个新键，它后面那几项就不渲染了。
> 改成接在这组末尾后，内置项的前后关系不变，那两行应当正常。若是你那边仍然看不到那两行，用「配置 → 编辑 JSON」把
> `provider_tts_settings` 整段发我，插件这边不会再动 AstrBot 的字段结构。


## 不同机器人 / 不同会话用不同音色

不用填机器人 ID，全用 AstrBot 自己的机制：

1. 再建一个 OpenAI TTS(API) 提供商，Base URL 同上，`voice` 换成另一个音色
2. 在该会话发 `/provider tts` 看列表，`/provider tts <序号>` 切过去
3. 或在「会话管理 → 该会话规则 → 提供商配置 → TTS 提供商」里选

## 自检

```
/tts状态
```

会打印：当前版本、端点地址、是否已启动、模型、AI 页音色、插件配置音色、实际生效音色、兜底音色、Key 是否就绪。也可以直接访问 `http://127.0.0.1:8788/health` 看版本。

## 版本怎么认

插件卡片上的版本号由 AstrBot 读 `metadata.yaml` 的 `version` 自动显示（插件名右边的灰色数字），所以显示名保持纯名字 `Breeze TTS`，不在名字里重复写版本。

同一个版本号还出现在：

- 插件卡片版本（来源 `metadata.yaml` 的 `version`）
- `/tts状态` 首行：`Breeze TTS v3.7.8`
- AstrBot 日志：`breeze_tts v3.7.8 已加载`
- `GET /health` 返回的 `version`

## 插件配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `voice_id` | 空 | **语音回复音色 ID**，优先于提供商 `voice`（与 AI 页那一项同一个优先级链） |
| `port` | 8788 | 端点端口 |
| `api_key` | 空 | Breeze Key，留空则用提供商表单里的 Key |
| `base_url` | `https://api.breeze.blue` | 上游地址 |
| `default_voice` | 空 | 兜底音色；提供商里填的 voice 不是 `voc_` 时用它 |
| `model` | `breeze-tts-2` | 模型 ID |
| `instructions` | 空 | 表演指令，与正文同语种 |
| `guidance_scale` | 4.0 | 指令强度 1–10 |
| `speed` | 1.0 | 语速 0.5–2 |
| `timeout` | 60 | 单次请求超时（秒） |
| `max_chars` | 500 | 单次请求字数，超了按标点切段 |
| `proxy` | 空 | 出站代理（插件访问 Breeze 用） |

## 排障

| 现象 | 处理 |
|---|---|
| 语音没声音、仍发文字 | `/tts状态` 看端点是否启动；再看提供商是否选了、是否启用 |
| 「默认文本转语音模型」里没有我建的提供商 | 该提供商的 **启用** 开关没打开——没启用的提供商不会加载，也不会进候选列表；打开后保存再看 |
| 看不到「语音回复音色 ID」 | 刷新浏览器；日志里 AI页音色项=已注入/未注入 会直接说；未注入就填「插件配置 → 语音回复音色 ID」 |
| 「默认文本转语音模型」「TTS 触发概率」不见了 | 先刷新 / 重载插件；仍不见就把「配置 → 编辑 JSON」里 `provider_tts_settings` 整段发我（3.7.8 已把注入点挪到这组末尾，正常不该再影响这两行） |
| 日志报 `Address already in use` | 3.1.0 已处理：复用旧端点或自动换端口。若仍出现，`/tts状态` 会给出实际端口，按它改提供商地址 |
| 插件重载后 Key 不生效 | 确认插件目录里生成了 `runtime_config.json`；改动配置后重载一次即可 |
| 端点未启动 | 端口被占用，改 `port` 后重载插件；日志里有「端口 xxx 绑定失败」 |
| 401 / 402 | Key 无效或额度用尽；Breeze 日志页可查 |
| 422 | 多为 model 与语言不匹配：中文用 `breeze-tts-2`，其他语种换 multilingual |
| 长句被拒 | Breeze 单次上限 1000 字符，插件默认 500 自动切段，可调 |
| 声音是别人 | 先看「AI → 语音回复 → 语音回复音色 ID」和「插件配置 → 语音回复音色 ID」是否填了；前者优先级最高，会覆盖提供商的 voice |

## 计费

1 credit = 10 个计费字符；**中文每个汉字算 2**，标点也计。Free 每天 400 credits ≈ 2000 汉字。
同一句话重复请求会重复计费，降低 TTS 触发概率能省额度。

## 版本记录

- `3.7.8` 新增插件配置项 `按角色保留音色`（`voice_fallback_only`，默认关闭）。关闭时保持现状：AI 页音色覆盖所有角色；开启后：哪个提供商自己在 voice 里填了 `voc_` 音色就按各自的走，AI 页那项只在请求没带 `voc_` 时兜底——多角色各挂一个提供商时互不串音。日志来源会显示成 `提供商voice（按角色，AI页仅兜底）`
- `3.7.7` 修「重启后配置页那一栏是空的」：配置页拿到的展示用 config 可能就是 `DEFAULT_CONFIG`（`ConfigProfileService.get_profile_schema()` 直接返回 `"config": DEFAULT_CONFIG`），所以插件在截获/回填音色时，除了写运行中的 config，也把值同步进 `DEFAULT_CONFIG` 的同一项；加载日志末尾会多出一段 `AI页音色ID=…`，直接看得到运行配置里的实际值
- `3.7.6` 换成「保存即截获」：hook `AstrBotConfig.save_config`，在用户点保存的那一刻从提交体里取 `provider_tts_settings.breeze_voice_id` 并写进 `runtime_config.json`，音色当场生效、重启也不丢；提交体里没有该字段时会打日志`保存配置时光标里没有「语音回复音色 ID」——配置页没提交该字段`，用来定位是前端没提交还是被清理
- `3.7.5` 补齐持久化的另一半：`AstrBotConfig.check_config_integrity(refer_conf=DEFAULT_CONFIG, ...)` 会把「参照默认值里没有的键」直接删掉（日志 `Config key removed: provider_tts_settings.breeze_voice_id`），所以除 schema 之外，本版还把该键补进 `DEFAULT_CONFIG` 和运行中的 config 对象；这样保存时用户输入不会被清掉，重启也能靠 `runtime_config.json` 回填
- `3.7.4` 与 `astrbot_plugin_zhipu_search` 的做法对齐：那个插件只往**已存在字段**的 `options` 里追加候选值，所以值写在内置键上，重启不丢；它自己的 README 还写明旧版注入的新键（`websearch_zhipu_key`）**「会被 AstrBot 启动时当作未知配置清除」**，v1.2.0 起改放插件配置。本版据此把音色做成双向同步：AI 页读到值就存进 `runtime_config.json`，启动时若配置里没有该键就用缓存回填，保证输入框重启后仍显示并继续生效
- `3.7.3` AI 页音色一读到就固化进 `runtime_config.json`（`voice_cache`），避免重启时 AstrBot 清掉未知键导致音色丢失；`/tts状态` 会显示「来自缓存」的音色
- `3.7.2` 「语音回复音色 ID」填了就不再校验 `voc_` 前缀（填错由上游报错，不再静默忽略）；合成日志加「来源」（AI页音色ID / 插件配置voice_id / 提供商voice / 插件default_voice）；`/tts状态` 直接报告运行配置里到底有没有 `breeze_voice_id` 这个键，用来自证「填了但没存进去」
- `3.7.1` 合成成功时打一行日志（voice / 字数 / 音频字节 / 耗时），用于确认「到底是没触发 TTS，还是触发了但发出去的不是语音」
- `3.7.0` 恢复「AI 页音色子项」：标签仍是中文，注入点改到 `provider_tts_settings.*` 这一组的末尾，不再打断内置「默认文本转语音模型」「TTS 触发概率」的渲染；受 AstrBot 内部机制限制，这一项不会随语音回复开关收起；插件配置的 `voice_id` 保留为同一优先级链条的第二顺位
- `3.6.0` 撤掉过一版 AI 页注入，只保留插件配置面板（本版已恢复）
- `3.5.1` 音色 ID 项加 `condition`，与内置「默认文本转语音模型」一致：语音回复关闭时收起、打开时展开；修复由此暴露的递归注入死循环（跳过 `condition` 与刚插入的项）；给 i18n 转换函数打补丁，把被换成键名的中文标签还原
- `3.5.0` 音色 ID 双通道：AI 页注入项之外，插件配置面板也加 `voice_id`（标签自控，不依赖 AstrBot 的 i18n 词条）；优先级 = AI 页 > 插件配置 > 提供商 `voice` > `default_voice`；`/tts状态` 分别打印两处值与实际生效值
- `3.4.0` 注入改为递归查找（不再写死 `ai_group.items`，同时兼容 `ai_group.metadata.<分组>.items` 这类分层结构）；找不到时日志打出 schema 顶层键，便于定位
- `3.3.0` 音色子项改为常显（不再被「语音回复」开关隐藏）；注入同时覆盖 `CONFIG_METADATA_3` 与运行中的配置对象；音色值在插件侧留一份缓存，AstrBot 重启清掉未知键后自动写回
- `3.2.0` 在「AI → 语音回复」下面自动注入「语音回复音色 ID」子项，填了优先于提供商里的 voice
- `3.1.1` 显示名去掉版本号（AstrBot 已从 `metadata.yaml` 自动显示版本，避免重复）
- `3.1.0` 修复重载后端口被占用（复用已有端点 / 自动顺延并报告实际端口）；配置落盘 `runtime_config.json`，旧端点也能读到新配置；修掉未读请求体导致的连接重置
- `3.0.0` 改为进程内 OpenAI 兼容端点，配合内置「OpenAI TTS(API)」卡片；去掉角色预设，音色由提供商决定
- `2.0.0` 尝试注册原生 TTS 提供商类型（该列表为内置固定，未生效）
- `1.1.0` 支持按机器人分配音色（消息链装饰方案）
- `1.0.0` 首个版本
